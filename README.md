# Slime 2026

Полноценный real-time мессенджер в духе Telegram: аккаунты с сессиями и 2FA,
личные и групповые чаты, каналы, медиа, истории (stories), звонки,
темы/обои/i18n — всё на живых данных, без моков.

**Slime** — это имя и лицо проекта (раньше он сам себя называл «Telegram Clone»):
фирменный логотип-глоб с глазами и каплей, favicon `/favicon.svg`, зелёные бренд-палитры (тёмная `#0d1b14`, светлая мятная),
кислотно-зелёный акцент `#2ad46e` с тёмным текстом на нём, градиентные primary-кнопки и исходящие
пузыри, обложка меню в бренд-градиенте. Геометрия и механики при этом
не менялись — они портированы из tdesktop. Акценты демо-аккаунтов (`alice`,
`bob`) и их радиус пузырей были сброшены при редизайне, чтобы новая тема
включилась сразу; свои акценты и радиус можно вернуть в «Настройках».

Это учебный клон, **не** копия всех возможностей Telegram. Список того, чего
намеренно нет, — в разделе [«Чего в этом нет»](#чего-в-этом-нет), тщательно
и честно, без декоративных заглушек.

## Быстрый старт

Требуется Node.js ≥ 20 (используется встроенный `node:sqlite`, проверено на Node 22–24).

```powershell
# вариант A — одна команда (PowerShell/macOS/Linux)
git clone <репозиторий> telegram-clone
cd telegram-clone
npm install        # ставит и корень, и server/, и web/ (postinstall)
npm run dev        # поднимает сервер :3001 и Vite :5173 вместе

# вариант B — два терминала
cd server && npm install && npm run start      # API + Socket.IO на :3001
cd web    && npm install && npm run dev        # Vite на :5173, прокси на 3001
```

**Готово.** Откройте http://localhost:5173 (dev) или http://localhost:3001
(собранная сборка, если `web/dist` уже построен через `npm run build`).

Тестовые аккаунты (создаются при первом входе, пароль у обоих `secret123`):

| логин  | имя   |
|--------|-------|
| `alice`| Алиса |
| `bob`  | Боб   |

Чтобы посмотреть real-time в одиночку: нажмите «Регистрация» и заведите
второго пользователя — сообщения, реакции, печатание и звонки приходят
мгновенно в другой сессии.

База данных: SQLite (WAL) файл `data/app.db`. С чистого листа: остановите
сервер и удалите файл — при старте создастся заново.

## Архитектура

```
telegram-clone/
├── scripts/           dev.mjs (два процесса одним npm run dev), install-all.mjs
├── server/            Node 24 ESM, без избыточных зависимостей
│   └── src/
│       ├── index.js   HTTP+Socket.IO, /api/upload (multer 512 МБ), SPA-статика
│       ├── api.js     REST: auth/2fa/me/chats/messages/stories/calls/sessions
│       ├── db.js      node:sqlite схема + запросы (users, chats, members,
│       │              messages, edits, reactions, stories, stories_views,
│       │              calls, sessions)
│       ├── state.js   онлайн-карта, socket-комнаты
│       ├── totp.js    свой TOTP (RFC 6238) для 2FA
│       └── util.js    parseJSON/uid/валидация
├── web/               Vite + React 18 + TypeScript + zustand
│   ├── src/components/  Auth, Sidebar, ChatView, Composer, Message, Modals,
│   │                    Settings, ProfileEdit, Stories, Wallpaper, CallOverlay
│   ├── src/lib/         store.tsx (zustand + socket), api.ts, call.ts,
│   │                    theme.ts, i18n.ts (ru/en), media.ts, types.ts
│   └── e2e/             smoke.mjs (REST-смоук), call.mjs (сигналинг звонков)
├── data/app.db        SQLite-база (создаётся автоматически)
└── uploads/           загруженные файлы (раздаются со сроком кэша 7 дней)
```

- **Порты** — сервер: `:3001` (`/api`, `/uploads`, статика(dist)), dev-клиент:
  `:5173` (Vite проксирует `/api`, `/uploads`, `/socket.io` на 3001).
- **Auth** — Bearer-токен (localStorage `tg_token`) и для REST, и для
  Socket.IO (handshake auth). Сессии хранятся в БД, можно отзывать
  по одной или «выйти со всех устройств».
- **Realtime** — Socket.IO-комнаты `chat:<id>`; события `msg:new/update`,
  `typing`, `presence`, `chat:new`, `call:*`. Оффлайн-пополнения идут
  через REST-синк (`/api/sync`) при загрузке.

Честно: код — локальный хеш в localStorage (`tg_passcode`), состояние — `tg_passcode_lock`; это блокировка интерфейса браузера, не серверная защита |
| Чёрный список | как privacy.blocked в tdesktop: «Заблокировать/Разблокировать» в карточке профиля, раздел «Заблокированные» в Настройках → Приватность (список + разблок). Сервер запрещает отправку в личный чат, если любая сторона в блоке (403 `you_are_blocked` / `blocked_target`), тост подсказывает кто кого заблокировал. Хранение — `settings.blocked` у пользователя |
| Режим призрака | `settings.privacy.online = false`: сервер не рассылает presence «онлайн» и не обновляет last_seen, переключение на лету гасит/зажигает статус у всех участников |

| Обои | общие и персональные на чат; выбор пресета применяет фон сразу (как в Telegram); фон чата перекрывает общий; пресет «plain» — ровный тёмный градиент; стандартный фон теперь без объектов (узор доступен только явным выбором плитки «Узор») |
| Язык | ru/en переключение на лету |
| Уведомления | в-приложении (звук + тост), счётчики непрочитанных |
| Приглашения | `#/join/<chatId>` — ссылка-приглашение для групп и каналов |

## API (кратко)

Все пути под `/api`, авторизация `Authorization: Bearer <token>`:

```
POST  /auth/register | /auth/login | /auth/logout | /auth/logout_all
POST  /auth/2fa/setup | /auth/2fa/enable | /auth/2fa/disable
GET   /me, PATCH /me, POST /me/reset, PATCH /me/password
GET   /sync                       # буст-синк: me + chats + users
GET   /users, /users/:id
GET   /chats, POST /chats, GET/PATCH/DELETE /chats/:id
POST  /chats/join/:id             # вход по ссылке-приглашению
POST  /chats/:id/members, DELETE /chats/:id/members/:uid, POST /chats/:id/role
PATCH /chats/:id/member           # mute/pin/draft/notif/wallpaper (личные)
GET   /chats/:id/messages?before=&limit=&search=
POST  /chats/:id/messages         # type: text/photo/…/poll; media={}, scheduleAt
GET   /chats/:id/scheduled
POST  /messages/:id/edit|delete|pin|react|pollvote|forward, GET history
POST  /chats/:id/read
GET   /stories, /stories/archive, /stories/user/:id
POST  /stories, /stories/:id/view|pin|archive, GET /stories/:id/views
GET   /calls
GET   /sessions, DELETE /sessions/:token
POST  /upload                     # multipart, ≤512 МБ → /uploads/<name>
```

Socket.IO события клиента→сервера: `typing`, `chat:join-room`,
`call:start|accept|decline|end|signal`. Сервер→клиент: `msg:new|update`,
`typing`, `presence`, `chat:new|update`, `call:incoming|ringing|accepted|ended|s`,
`force:logout`.

## Тесты

```powershell
cd web
node e2e/smoke.mjs      # 9 проверок REST: логин, чаты, сообщение, реакция,
                        # опрос, голос, сторис, раздача UI; exit-код 0/1
node e2e/call.mjs       # сигналинг звонка alice→bob: 7 проверок — incoming/ringing,
                        # busy второму звонку, declined, accepted, ice-обмен, ended,
                        # записи в /api/calls
node e2e/blacklist.mjs  # чёрный список: alice блокирует bob → 403 you_are_blocked,
                        # встречный блок → 403 blocked_target, разблок → отправка
                        # снова работает (пробное сообщение удаляется)
```

`smoke.mjs` складывает сообщения в отдельную группу «Smoke Тест», чтобы не
загрязнять реальные чаты. Проверки вживую во время разработки проводились в
браузере двумя вкладками (prod-сборка и dev-сервер) — сообщения, реакции,
редактирование, черновики, закрепление, вход по ссылке и звонки-сигналинг
проверены end-to-end.

## Звонки (механики перенесены из Telegram Desktop)

Экран звонка, автомат состояний и серверная логика сверены с исходниками
`Telegram/SourceFiles/calls/` (calls_call.cpp, calls_panel.cpp,
calls_emoji_fingerprint.cpp):

- **Автомат состояний как в tdesktop** — incoming → ringing → connecting →
  connected, плюс отдельные «Переподключение…» (disconnected даёт 12 с на
  восстановление связи) и «Плохое соединение» с кнопкой **Повторить** (звонок
  обрывается только на окончательном `failed`, а не на каждом дисконнекте).
- **Занято (busy)** — позвонить пользователю, который уже в звонке, нельзя:
  вызывающий сразу получает `reason=busy`. Активный звонок закрывается при
  обрыве сокета (иначе «зомби»-звонок занимал бы линию навсегда).
- **Звонки попадают в историю чата** — на miss/decline/end сервер кладёт
  service-сообщение «📞 Пропущенный звонок / Звонок отклонён / Звонок · 02:41»
  (длительность считается от момента принятия, не от «позвонил»). Если личного
  чата ещё нет — он создаётся первым звонком.
- **Пропущенный по таймеру** — через 45 с без ответа звонок помечается
  `missed` у обеих сторон (как «не отвечает» в tdesktop).
- **Эмодзи-подтверждение шифрования** — точный порт calls_emoji_fingerprint:
  тот же набор из 333 эмодзи и то же деление sha-256 на 8-байтовые индексы.
  В веб-версии вход — DTLS-отпечатки обеих сторон SDP (в tdesktop — SHA256
  auth-ключа MTProto), поэтому эмодзи совпадают у обоих участников одного
  реального соединения и меняются от звонка к звонку.
- **Кольцо уровня микрофона** — реальный WebAudio-анализатор вокруг аватара
  (как индикатор Level в tdesktop), **индикатор качества связи** — по RTT из
  `getStats` (отличная/хорошая/плохая), **иконка «в тишине»**, когда remote
  microphone заглушен (track mute).
- **Управление как на референсе**: Экран / Вкл. видео / Микрофон / Завершить /
  Вкл. звук с подписями и **меню устройств** (`enumerateDevices` +
  `replaceTrack`, динамики — через `setSinkId`); на входящем — крупные
  «Отклонить/Ответить» (+ «Видео-ответ»: ответ без камеры камерой не включает).
- **Демонстрация экрана** — идёт **отдельным видео-треком** (вторая m-line,
  как в tdesktop): камера при этом не заменяется и работает параллельно.
  Доступна и в аудиозвонке (звонок переводится в видео, при выключении
  возвращается к звуку; если собеседник ещё показывает свой экран —
  «видео» сохраняется). Обмен состояниями (`call:state`) синхронизирует
  kind/экран/тишину/качество между сторонами.
- **Выбор качества демонстрации при включении** — клик по «Экран» открывает
  меню пресетов: «Как есть · до 60/с» (без ограничений), 1080p·30, 720p·24,
  480p·15, 360p·10. Пресет применяется `getDisplayMedia`-ограничениями и
  дожимается `applyConstraints` (contentHint=detail для читаемости текста);
  выбранный пресет передаётся второй стороне — у получателя в статусе
  показывается бейдж «Демо · 720p · 24», у отправителя — уголок на
  большом виде.
- **Компоновка вида (как в tdesktop)** — СВОЯ трансляция — большой вид
  (уголок «Демо · 720p·24»); чужая демка — мини-окно с подписью «Экран
  собеседника» (когда оба показывают), иначе мини-окно показывает камеру
  собеседника. Своя камера всегда в правом мини-окне. Прекращение любой
  демонстрации честно переключает большие виды у обеих сторон.
- Ошибки: mic-доступ падает в тост; у собеседника «Не в сети» — сразу
  «Пользователь не в сети».

## Чего в этом нет (честно)

- **SMS/Email коды** — при регистрации никакой внешней отправки нет, это
  личные аккаунты в локальной БД.
- **Сквозное шифрование (E2E)** — трафик между клиентом и сервером идёт по
  вашему HTTP(S), но на сервере сообщения хранятся в открытом виде. Шифрование
  звонка — DTLS WebRTC (стандарт), но это не MTProto-схема tdesktop.
- **Групповые звонки** — только 1:1 сигналинг (SFU-арена как в tdesktop не
  портирована).
- **AI-фоны для камеры** (как в Telegram для видео-звонков) — нет.
- **Мощный серверный поиск по всем чатам сразу** — поиск только в рамках
  одного чата и по пользователям.
- **Мобильные приложения/пуш** — веб-приложение адаптивно (мобильный вид
  включается на узких экранах), но настоящих WebPush нет.
- **Списки устройств в меню** — пока браузеру не выдан доступ к камере/
  микрофону, `enumerateDevices` отдаёт пустые имена: названия устройств
  появляются после первого разрешения (ограничение Chrome/Firefox, не баг).
- **Серверные папки-фильтры чатов** — вкладки над списком клиентские; full-фолдеры Telegram (folder CRD + подписки) не реализованы.
- **Зашифрованное хранение код-пароля** — см. «Код-пароль (лок)»: лок интерфейса, честный localStorage-хеш, не крипто-хранилище.
- **Ограничения звонков в этой среде** — WebRTC-медиа нуждается в
  микрофоне/камере. Если браузер запретил доступ, звонок честно падает с
  тостом «Нет доступа к микрофону/камере…»; сигналинг при этом работает
  (проверяется `web/e2e/call.mjs`).

## Сборка и запуск «как в прод»

```powershell
npm run build       # = vite build → web/dist
npm run server      # сервер :3001 раздаёт dist, /api и /uploads
```

Если `web/dist` отсутствует, сервер отдаёт только API — UI надо собрать
или использовать dev-режим Vite.

## Известные ограничения

- SQLite — единая точка записи; для одного инстанса достаточно, для кластера нет.
- Загрузки идут на диск (`uploads/`) без прокладки CDN; лимит 512 МБ на файл.
- `npm run dev` (одна команда) под Windows требует, чтобы `npm.cmd` был в PATH;
  в случае проблем используйте вариант B (два терминала).
